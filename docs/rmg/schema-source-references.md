## Connection Type Semantics

- Valid `ConnectionType` values are `Default`, `Direct`, `GladiatorArena`, `Portal`, and `Proximity`. Source: `GameEngineMapGenerator/MapGenerator/ConnectionType.cs:3`.
- Ground/adjacency helpers define behavior: `Direct` and `GladiatorArena` need ground connections; `Default` can have a ground gate but does not force adjacency; `Proximity` forces adjacency but no ground gate; `Portal` is neither. Sources: `GameEngineMapGenerator/MapGenerator/Utils.cs:189`, `GameEngineMapGenerator/MapGenerator/Utils.cs:198`, `GameEngineMapGenerator/MapGenerator/Utils.cs:207`.
- Zone embedding uses `NeedsGroundConnection()` for drawn zone links and `NeedsAdjacency()` for proximity/adjacency constraints. Source: `GameEngineMapGenerator/MapGenerator/ZoneMapper.cs:39`.
- Gate placement considers only `CanHaveGroundConnection()` connections. Source: `GameEngineMapGenerator/MapGenerator/Gates.cs:194`.
- `GladiatorArena` reserves gate space and throws if no arena gate can be placed. Sources: `GameEngineMapGenerator/MapGenerator/Gates.cs:584`, `GameEngineMapGenerator/MapGenerator/Gates.cs:589`.
- Portal encounters are placed for non-`Proximity` connections without valid gates, but portal buildings/pairs are created only for `ConnectionType.Portal`. Sources: `GameEngineMapGenerator/MapGenerator/Encounters.cs:121`, `GameEngineMapGenerator/MapGenerator/ContentPlacer.cs:701`, `GameEngineMapGenerator/MapGenerator/ContentPlacer.cs:727`.
- Template examples: `Direct` in `external/map_templates/All Around.rmg.json:1075`, `Portal` in `external/map_templates/Blitz.rmg.json:862`, `GladiatorArena` in `external/map_templates/Symmetry.rmg.json:379`, and `Proximity` in `external/map_templates/Yin Yang.rmg.json:729`.
- Runtime guard reaction values are `Aggressive`, `Negative`, `Common`, `Friendly`, `Peaceful`, and `Docile`; `NUM` is a sentinel. Source: `/mnt/Gaming/SteamLibrary/steamapps/common/Heroes of Might and Magic Olden Era/AssetRipper_export_20260505_154541/Scripts/Hex/Hex/Configs/ESquadReactionType.cs:6`.

## Rule Parsing

- Placement rules support `Random`, `Sid`, `MainObject`, `Crossroads`, `Connection`, `Road`, and `MandatoryContent`; the parser stores `target`, `targetMin`, `targetMax`, `weight`, and resolves typed indices. Sources: `GameEngineMapGenerator/MapGenerator/PlacementRuleType.cs:3`, `GameEngineMapGenerator/MapGenerator/PlacementRule.cs:8`, `GameEngineMapGenerator/MapGenerator/PlacementRuleHandler.cs:216`.
- `Connection` placement rules reject `Proximity` connections and require the named connection to touch the current zone. Sources: `GameEngineMapGenerator/MapGenerator/RuleParseUtils.cs:50`, `GameEngineMapGenerator/MapGenerator/RuleParseUtils.cs:66`, `GameEngineMapGenerator/MapGenerator/RuleParseUtils.cs:72`.
- Biome rules support `FromList`, `MatchZone`, and `MatchMainObject`; `differentFrom:` is parsed inside `FromList`. Sources: `GameEngineMapGenerator/MapGenerator/BiomeRuleType.cs:3`, `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:930`, `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:956`.
- Faction rules support `FromList` and `Match`; `differentFrom:` requires a main-object index, optionally plus zone name. Sources: `GameEngineMapGenerator/MapGenerator/FactionRuleType.cs:3`, `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:1024`, `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:1049`.
- Road configs use `RoadType` plus `RoadTargetConfig` endpoints; endpoint types mirror `Crossroads`, `MainObject`, `Connection`, and `MandatoryContent`. Sources: `GameEngineMapGenerator/MapGenerator/RoadConfig.cs:6`, `GameEngineMapGenerator/MapGenerator/RoadTargetType.cs:3`, `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:487`.

## Validation Pitfalls

- Enum parsing is exact and case-sensitive. On failure it returns `false` but also falls back to the enum's first value; many callers only log config errors. Sources: `GameEngineMapGenerator/MapGenerator/EnumParser.cs:23`, `GameEngineMapGenerator/MapGenerator/EnumParser.cs:47`, `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:127`.
- Invalid placement rules are omitted after logging because parsed rules are added only when `TryParseRule()` succeeds. Sources: `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:456`, `GameEngineMapGenerator/MapGenerator/PlacementRuleHandler.cs:219`.
- Invalid road endpoints cause the road to be skipped, not thrown. Sources: `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:491`, `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:514`.
- `guardReactionDistribution` must contain exactly 6 values; otherwise it logs and uses defaults. Sources: `GameEngineMapGenerator/MapGenerator/ContentPlacer.cs:1160`, `GameEngineMapGenerator/MapGenerator/MapDescription.cs:247`.
- `contentCountLimits` in `Zone` is `string[]`, but shipped JSON has scalar strings in two places; strict tooling should normalize or flag them. Sources: `GameEngineMapGenerator/MapGenerator/RandomMapTemplate.cs:56`, `external/map_templates/Crossroads.rmg.json:64`, `external/map_templates/Memory Lane.rmg.json:404`.
- `guardZone` is silently reset to `-1` unless it names either endpoint zone. Source: `GameEngineMapGenerator/MapGenerator/MapDescriptionBuilder.cs:385`.
- `MainObjectPlacement.Connection` only accepts ground-required connections, so `Default`, `Portal`, and `Proximity` are rejected for that placement mode. Source: `GameEngineMapGenerator/MapGenerator/ZonePartition.cs:562`.
- Official templates contain connection-level `road`, `simTurnSquad`, and `guardRandomization`, but those fields are absent from the inspected `RandomMapTemplate.Connection` C# type and should be treated as preserved compatibility fields.
